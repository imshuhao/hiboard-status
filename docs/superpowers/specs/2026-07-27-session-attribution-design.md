# 会话归属修复（v0.2.4）· 设计文档

日期：2026-07-27 · 状态：已实现（用户批准直接实现）

## 问题（真机实测发现）

1. **归属漂移**：hook 事件的 `cwd` 跟随会话 shell 的 `cd` 变化，会话中途
   切目录后，状态被记到错误的项目名下（实测：本插件开发会话的摘要挂到了
   `hiboard-status` 而非启动目录 `shuhao`）。
2. **幽灵会话翻状态**：桌面 App 在回合间回收/重启 CLI 进程，产生秒开秒关、
   无指令的会话（一小时内 3 个不同 session_id），其 SessionEnd 把正主项目
   翻成「已结束」。

## 方案

| 规则 | 实现 |
|---|---|
| 归属钉死在启动目录 | SessionStart 时把 `session_id → 项目名` 写入 `state.sessions`，后续事件按 session_id 查表；查不到（插件启用前的会话）退回按 cwd 推断 |
| SessionEnd 守卫 | 仅当项目条目记录的 `session_id` 与事件一致（或条目无 session_id）才置 ended；条目不存在则完全跳过（不建条目、不推送） |
| 映射过期 | `state.sessions` 随 7 天清理（`ts` 每次查表刷新） |

局限（接受）：幽灵会话自己的 SessionStart 仍会短暂把项目置为 running——
它确实发生了，无法与真实会话区分；守卫只保证它不能覆盖正主的后续状态。
