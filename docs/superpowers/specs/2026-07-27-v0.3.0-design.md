# v0.3.0 · 九项批量改进 · 设计文档

日期：2026-07-27 · 状态：已批准（用户：「123456789全都做掉吧」）

| # | 项 | 设计要点 |
|---|---|---|
| 1 | 后台推送+事件合并 | hook 路径不再同步推送：`request_push()` 在锁内认领 `flush_claim`（45s 过期），认领成功才 spawn 分离的 `--flush <debounce>` 进程；flusher sleep（默认 3s，配置 `pushDebounce`）→ 清除认领 → `do_push()`。窗口内连发事件只推最终状态；清除认领在推送前，推送期间的新事件会拉起新 flusher，不丢更新。`HIBOARD_NO_FLUSH=1` 退回同步（测试/逃生门） |
| 2 | `--status` | 只读 CLI：版本、配置状态、配额熔断至何时、最近推送时间（新增 `last_push_ts`）、各项目状态行、主题卡登记簿、轮转卡位年龄、今日 PUSH_FAIL 计数。恒 exit 0 |
| 3 | 多机 cardSuffix | 配置 `cardSuffix`（默认空=现状，不动老用户的卡）；状态卡与 --test-push 的 card_id 变为 `claude_code_status_<slug(suffix)>` |
| 4 | 运行时长 | running/waiting 的时间戳前缀渲染为 `` `自 14:32` ``（静态文本，无需刷新） |
| 5 | 摘要跳过琐碎回合 | 回复压缩后 ≤ `summaryMinChars`（默认 120 UTF-16 码元）时原文即摘要，不起 LLM |
| 6 | 摘要质量 | 新增 `last_turn()` 同时提取最后用户指令；LLM prompt 带上「用户的指令是：…」上下文。`last_assistant_text` 保留为兼容薄封装 |
| 7 | 主题卡登记簿 | 主题推送成功后登记 `state.topics[card_id] = {topic, ts, count}`；`--status` 可列出名下永久卡 |
| 8 | Windows 尽力而为 | store 文件锁 fcntl→msvcrt 双实现；分离进程 spawn 按 os.name 选 start_new_session / DETACHED_PROCESS。未经真机验证，README 如实声明（且需 python3 在 PATH） |
| 9 | 发布卫生 | CHANGELOG.md（0.1.0 起）；git tag v0.3.0 并推送；README/设置文档同步 |

不变量继续成立：hook 恒零、未配置零副作用、递归守卫、authCode 不落日志、
摘要只写 summary/summary_ts、CLI 失败非零。验收：全部现有测试语义不变通过 +
每项新行为有测试。
